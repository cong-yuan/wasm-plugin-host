# 测试

> 共 **123 个测试**,全部通过,零警告:
> * `wasm-plugin-host`:67 集成(33 生命周期等 + 9 磁盘缓存 + 22 日志/配置/能力 + 3 WASI runtime)
>   + 14 单元(本文件主体)
> * `dsh-wasm-host`:6 + 13 + 10 集成 + 12 单元 + 1 doctest(见文末「六」)
> 命令:`cargo test --release`
>
> 外壳/UI 的测试在别处:studio 的 `src-tauri/tests/studio.rs`(66 个,
> 其中 3 个专测 `hana-shell` 的槽位面)与 `plugins/hana-shell` 的 node harness
> (`npm test`,75 条断言)。
> 见 [仿照-openhanako-外壳.md](仿照-openhanako-外壳.md)。
>
> 集成测试是**自包含**的:用 WAT(`wat` crate)在进程内构造最小 wasm 插件,
> 不需要 `cargo build` 一个 wasm。这使得测试快(0.27s)且 hermetic。

## 五、测试覆盖的空白(诚实)

| 空白 | 原因 / 计划 |
|---|---|
| 权限拒绝 / fuel 超限 | 功能未实现(P0) |

## 六、`dsh-wasm-host` 的测试(33)

新 crate 的测试与 `host` 互补:它们验证**两个系统组合后**的行为。
插件用 WAT 内联编译,无需构建 wasm、无网络。

### 集成 —— `tests/agent_loop.rs`(6)

| 测试 | 验证了什么 |
|---|---|
| `wasm_tool_is_registered_on_dsh_tools_service` | guest 工具出现在 dsh `ctx.tools` 上 |
| `agent_loop_drives_a_wasm_tool_and_logs_its_result` | **dsh 真实 agent loop** 驱动 guest 工具,结果进 session |
| `calling_an_unknown_wasm_tool_is_a_structured_error` | 未知工具是结构化错误,不是 panic/trap |
| `wasm_tool_removed_when_host_fiber_is_disposed` | 卸 fiber → 工具从 `ctx.tools` 反注册 |
| `two_wasm_plugins_register_distinct_tools` | 多个 guest 共存 |
| `unload_after_install_still_leaves_host_consistent` | `unload` + `resync_tools` 同步工具面 |

### 集成 —— `tests/flow_bridge.rs`(5)

| 测试 | 验证了什么 |
|---|---|
| `guest_veto_blocks_a_tool_call_through_the_real_agent_loop` | guest `veto` → dsh `DENIED`(直接调用 + 真实 loop 两路)|
| `guest_hook_can_run_without_a_tool_surface` | 纯 hook 插件(无工具)也能桥接 |
| `observe_fanout_does_not_alter_the_session_log` | observe 钩子无法否决 |
| `pre_step_veto_rejects_the_turn` | guest `veto` 在 `agent/pre-step` 拒整个 turn(已验证:禁用 veto 时此测试会失败)|
| `observe_listener_alone_mounts_and_continues` | 只装 observe 桥不影响正常 turn |

### 集成 —— `tests/per_slot_plugins.rs`(9) —— 每个 slot 一个 cordis 插件

| 测试 | 验证了什么 |
|---|---|
| `each_slot_gets_its_own_fiber` | 两个 slot → 两个独立 fiber;dispose 一个不影响另一个 |
| `a_slot_stays_pending_until_its_inject_is_provided` | inject 未满足 → fiber **PENDING**,工具不注册 |
| `providing_the_service_activates_the_pending_slot` | provider 出现 → 依赖方收敛为 **Active**,工具出现 |
| `a_wasm_provided_service_is_requireable_by_other_dsh_plugins` | wasm 的 `provides` → dsh 插件可 `require::<WasmService>` 并调用 |
| `a_wasm_service_disappears_when_its_slot_is_disposed` | dispose slot → 服务撤回 |
| `a_dsh_service_can_satisfy_a_wasm_slots_inject` | dsh 服务(declare_dsh_service)满足 wasm 的 inject |
| `each_slot_provides_independently_and_tools_are_attributed_by_slot` | 服务按 slot 各自归属 |
| `resync_slot_tools_only_touches_the_named_slot` | 单 slot 工具面 resync |
| `agent_loop_still_drives_a_per_slot_wasm_tool` | 拆分后 agent loop 仍能驱动 wasm 工具(回归)|
