# 插件扩展协议

> 本文定义插件“能扩展什么”。安全边界见 [能力与权限模型.md](能力与权限模型.md)。
> 目标是把 Tool、Hook、Service、UI 统一成一个可演进的 Extension Contract。

## 1. 插件的四个扩展面

```text
Plugin
├─ Tools       主动被 Agent 调用的能力
├─ Hooks       介入 Agent 生命周期
├─ Services    插件之间的命名能力
└─ UI          前端槽位、页面、窗口、主题与受控交互
```

四个面共享稳定 slot identity、lifecycle、config、capability、resource limits、audit、atomic reload，因此不再把“插件”理解成“Tool 的容器”。

## 2. Backend / Frontend 分层

```text
plugin package
├─ plugin.json
├─ backend.wasm
└─ ui/
   ├─ entry.js
   ├─ style.css
   └─ assets/
```

```text
backend.wasm  <-> Host capability APIs <-> Agent Kernel
     ^
     | controlled plugin bridge
     v
frontend UI   <-> Slot/Route/Window registries
```

后端与前端共享插件 identity，但不共享隐式权限。例如拥有 `filesystem.read` 不代表前端能调用任意 Tauri 命令。

## 3. Extension Manifest

建议把当前 `PluginDecl` 演进为如下逻辑结构（ABI v1 仍可用 JSON 表达）：

```json
{
  "name": "repo-assistant",
  "abi": 1,
  "tools": [{"name": "repo_search", "exec": "repo_search"}],
  "hooks": [{
    "on": "tools/pre-execute",
    "exec": "guard",
    "action": "veto",
    "priority": 100
  }],
  "injects": ["memory"],
  "provides": ["repo-index"],
  "ui": {
    "slots": [{"slot": "sidebar", "component": "repo-panel"}],
    "routes": [{"path": "/repo", "component": "repo-page", "title": "Repo"}]
  },
  "capabilities": {}
}
```

兼容现有声明时，`mode: "observe"` 可映射为 `action: "observe"`；`mode: "waterfall"` 继续接受。新插件优先使用显式 action。

## 4. Tool Contract

- 名称在 active registry 内唯一。
- 参数/结果继续使用 JSON。
- 每次调用受 plugin resource budget。
- Tool 的宿主副作用依赖 capability，不因为“它是 Tool”自动获得文件或网络权限。
- unload/deactivate 后工具立即消失。

## 5. Hook Contract

Hook 必须显式回答：事件、动作（observe/rewrite/veto）、优先级、失败策略。

| 家族 | 示例 | 常见动作 |
|---|---|---|
| `turn.*` | `turn/start`, `turn/end` | observe |
| `agent.*` | `agent/pre-step`, `agent/request` | observe/rewrite/veto |
| `model.*` / `assistant.*` | `assistant/chunk` | observe，部分点可 rewrite |
| `tool.*` | `tools/pre-execute`, `tool/result` | observe/rewrite/veto |
| `session.*` | session events | observe |
| `ui.*` | UI lifecycle | observe |
| `system.*` | runtime lifecycle | observe |

宿主维护 `EventSpec`；插件不能靠返回一个 veto JSON 就越权获得 veto 能力。

## 6. Decision Contract

```json
{"kind":"continue"}
{"kind":"rewrite","value":{}}
{"kind":"veto","reason":"..."}
```

新增规范：`rewrite.value` 必须通过 EventSpec schema 校验；`veto.reason` 必须进入最终 Dispatch，不能被宿主丢弃。

## 7. Service Contract

`injects/provides` 继续作为依赖图：

- provider 出现自动激活 consumer；
- provider 消失级联 deactivate；
- 调用按 service name；
- 重入继续返回 busy 而不是死锁；
- consume/provide 都受 capability；
- 将来可加 version/interface id；
- WIT 化时不改变 Registry convergence。

## 8. UI Contract

标准贡献类型：

```text
ui.slots
ui.routes
ui.windows
ui.theme
ui.adjusts
ui.commands
```

原则：

- 内置静态路由优先，插件不能静默覆盖；
- route 与 nav 由同一记录派生；
- slot 是语义锚点；
- theme 使用 token/变量；
- `adjusts` 是高权限扩展；
- 前端到后端只走带 plugin identity 的受控 bridge。

当前实现状态：sandboxed 的 slot provide/inject、route、window、adjust 与 assets 已在
`Plugin::load_with_policy` 的 stage 阶段校验 effective UI capability。Registry 另外暴露
`authorize_ui_action(authenticated_slot, UiHostAction)` 给真实 Studio/Tauri 前端宿主作为统一
运行时授权入口。`UiHostAction` 当前覆盖 backend command、theme、adjust、provide/inject/render
slot 与 open/close window；slot/window 类动作还必须命中该插件自己的 `UiDecl` 声明，因此
宿主 grant 只能收窄 manifest，不能把插件未声明的 UI 面在运行时放大。调用复用插件实例自己的 CapabilityGate 并写 AuditSink。**plugin slot identity
不属于 action payload**，必须由宿主的已认证上下文提供，不能相信 iframe/postMessage 中的
`source` 或自报 plugin id。真正的前端宿主源码不在本仓库，所以仍需在那个宿主里把原始
Tauri invoke 替换为这一受控桥。

## 9. 生命周期

```text
Discovered
  -> Loaded
  -> Quiescent
  -> Active
  -> Reloading
  -> Active | Quiescent
  -> Unloaded
```

Stage 阶段完成 ABI、manifest、capability、冲突、EventSpec、资源限制校验；Commit 后不再出现“替换旧插件后才发现声明非法”。

## 10. 版本策略

短期不需要 ABI v2：

- ABI v1：继续 core wasm + JSON。
- Extension Contract 独立版本化，例如 `manifest_version: 1`。
- Capability schema 独立版本化。
- EventSpec 在宿主版本内稳定，新增事件向后兼容。

只有改变导出/导入调用约定时才升 ABI。

## 11. 推荐实现边界

```text
capability.rs   requested/granted/effective + gate
limits.rs       fuel/memory/timeout/output budgets
event_spec.rs   event schema + allowed actions
audit.rs        bounded host-owned allow/deny/resource events
ui_policy.rs    UI contribution/bridge permission
```

避免把权限逻辑继续堆进 `runtime.rs` 或 `Registry`。

## 12. 核心不变式

1. 声明不是授权。
2. 一个 capability 只有一个强制执行入口。
3. reload 不扩大权限。
4. quiescent 插件没有 effects。
5. unload 回收 effects + capability handles。
6. 跨插件调用不继承调用方权限；callee 用自己的 capability。
7. 前端身份不可由 JS 自报字符串决定。
8. trusted 是兼容模式，不是第三方生态的安全边界。
