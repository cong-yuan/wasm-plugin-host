# 需求

> 这份文档说明 **wasm-plugin-host 要解决什么问题**、为什么选 WASM、以及明确的边界。
> 如果只读一份文档,读这个。

---

## 1. 一句话目标

给一个 **Rust 内核的 agent 应用(如 Codex 类 App)** 做一层**可运行时插拔的插件系统**,
使得:

1. 插件能在**不重启宿主**的前提下加载、卸载、热更新;
2. 插件能**介入宿主流程**(观察、改写、否决),而不只是被调用;
3. 插件之间能通过**服务图**互相依赖,provider 出现时 consumer **自动激活**;
4. 插件可以用**任意语言**写(Rust / Go / 将来 JS / Python),只要编译到 WASI;
5. **坏插件 / 坏构建不能拖垮宿主**。

---

## 2. 背景:为什么不是 dlopen,而是 WASM

最初的参考是 **dsh(deepseek-harness)** 的插件模式:Rust 用 `dlopen` 加载 `.dylib`,
通过 C-ABI 契约(`dsh-plugin-contract`)注册工具。这条路可行,但实测后有两个硬伤:

| 问题 | dlopen 的现实 | WASM 的解法 |
|---|---|---|
| **无法真正卸载** | 代码段永久驻留进程,直到退出(dsh 源码注释里明确写了 "never unmapped") | `drop(Instance)` **真的释放**代码 + 线性内存 |
| **崩溃/越界带崩宿主** | 同进程裸指针,一个 panic 或越界就可能带崩整个 App | 沙箱隔离,越界是 trap,宿主不受影响 |
| **跨语言困难** | 得用 C-ABI 手写适配 | 任何能编 WASI 的语言天然可用 |

**实测数据(Apple M2 Pro, wasmtime 44, release):**

| 指标 | 数值 |
|---|---|
| 实例化速度 | **~5 µs/个**(编译只做一次) |
| 空闲实例内存 | **~6 KB/个**(线性内存懒提交) |
| 计算性能 | **≈ 原生 0.95x**(真循环测试) |
| 跨边界调用 | **+16 ns** |
| 卸载(建+毁) | **~1.1 µs/个** |

结论:**WASM 是唯一同时满足"真隔离 + 真卸载 + 跨语言"的方案**,且性能代价可忽略。
这直接决定了技术选型。

## 3. 核心需求(按优先级)

### R1. 运行时插件生命周期 —— 【必须】
- 运行时 `load` / `unload` 插件
- **原子热更新**:重编译覆盖 `.wasm` 后,运行中的宿主自动换掉
- 卸载时**真正释放**代码与内存

### R2. 坏构建安全 —— 【必须】
> 这是整个系统的**安全底线**。

- 新构建必须**先完整校验**(ABI、导出、init、describe),**全部通过才拆旧的**
- 任何失败(坏 wasm / ABI 不符 / 缺导出 / 工具名冲突)→ **旧插件继续运行**

验证:`reload_is_atomic_on_broken_build`、`demo/broken-build.sh`

### R3. 插件介入流程 —— 【必须:这是"插件"的本意】
插件不能只是叶子工具,必须能**进入流程**:
- **observe**:看得到事件,不改流程(日志/指标)
- **rewrite**:改写流程携带的值
- **veto**:否决当前步骤

事件词汇对齐 dsh:`agent/pre-step`、`agent/request`、`llm/chunk`、`tools/pre-execute`、
`tool/result`、`turn/start`、`turn/end`、`tool/call`、`assistant/message`

验证:`plugin_can_veto_the_flow`、`observe_hook_cannot_change_flow`、`examples/intervene.rs`

### R4. 服务图 + 响应式收敛 —— 【必须】
- 插件声明 `injects`(需要什么)/ `provides`(提供什么)
- **inject 未满足 → 插件静默待命(quiescent),不注册任何 effects**
- **最后一个 provider 出现 → 自动激活(级联)**
- **provider 消失 → 级联停用依赖者**
- 跨插件调用按**服务名**(能力)而非 slot(实现)

验证:`consumer_stays_quiescent_until_provider_appears_then_converges`、
`deeper_chain_converges_in_one_pass`、`reload_respects_service_graph`

### R5. 配置驱动 + 实时更新 —— 【必须】
- 配置文件描述**期望状态**(desired state),`reconcile` 收敛
- 配置参数**注入插件**
- 配置变化时:**只更新配置变了的那个插件**,其他不动
- 每个插件可选策略:实时推送 或 重启自己

验证:`config_change_to_one_slot_leaves_the_other_untouched`、
`supervisor_updates_only_changed_slot_via_reconcile`

### R6. 语言无关日志 —— 【必须】
- 插件**用各自语言的惯用 print** 就能出日志,零胶水
- 依据:捕获 **WASI stdout/stderr**(所有语言的 print 都走这里)
- 有界缓冲(不泄漏)+ slot 标签 + 可选回调

验证:`guest_stdout_and_stderr_are_captured_as_logs`、`log_buffer_is_bounded`

### R7. 并发 —— 【必须】
- 池化分配器(池化模式支持大量实例)
- 并行调用(不同插件并行,同插件串行)
- 重入安全(嵌套服务调用不死锁)

验证:`pooled_allocator_loads_and_calls`、`parallel_calls_across_slots_run_and_preserve_order`、
`recursive_service_call_is_refused_not_deadlocked`

### R8. 文件监听 —— 【应该】
- 用 **notify 事件驱动**,不是轮询
- 监听 wasm **和配置文件**
- 平台不支持时回退轮询(明确提示,不静默)

验证:`notify_watcher_fires_on_file_change`;实测 30s fallback 下延迟 ~136ms

## 4. 明确的边界(不做什么)

| 不做 | 原因 |
|---|---|
| **不做完整 agent 实现** | 本项目只提供**可被介入的流程骨架**(`flow::run_turn`);真 LLM 调用由使用者替换 `Model::trait` |
| **不做权限/沙箱模型**(当前) | 明确列为最大短板,见下;当前给插件完整 WASI |
| **不绑定某一种语言** | ABI 是 JSON-over-linear-memory,任何 WASI 语言都能实现 |
| **不做 UI** | 宿主是库 + CLI;UI 由使用者(Tauri/其他)来做 |

---

## 5. 非目标与已知取舍

### 5.1 当前最大短板:无权限模型 🔴
**现状**:插件拿到的是**完整 WASI**,可以读写文件、访问网络。
**含义**:当前**不适合**直接跑"第三方不可信插件"。
**这是接下来最重要的工作**(见 [计划.md](计划.md) P0)。

### 5.2 其他已知取舍
- **Go 插件每实例 ~2.6 MB**(内置 Go runtime),Rust 只要 ~119 KB → 插件量大时优先 Rust
- **原生库无法真卸载**,但 WASM 可以 —— 这是选 WASM 的核心理由
- **服务只是"命名能力"**,目前插件间通过 `host.call_service` 传递 JSON,而非共享内存对象

## 6. 验收标准(整体)

一个满足需求的实现应当:

- [x] 运行时加载/卸载/热更新,坏构建不影响旧插件
- [x] 插件能 observe/rewrite/veto 流程
- [x] 服务图 + 响应式收敛(provider 出现自动激活 consumer)
- [x] 跨插件服务调用,重入安全
- [x] 配置注入 + 逐插件实时更新
- [x] 语言无关日志
- [x] 池化 + 并行调用
- [x] notify 事件驱动监听
- [x] 全部有自动化测试(32 集成 + 3 单元,全绿,零警告)
- [ ] **权限模型**(P0,未完成)
- [ ] **Tauri 集成**(P1,未完成)
- [ ] 磁盘编译缓存(P2,未完成)

## 7. 参考与来源

- **dsh (DeepSeek Harness)**:`dsh-rs` crate + `cordis-rust` 内核,提供了"一切皆插件 +
  Context/Fiber/服务图"的模型。本项目的事件词汇、inject/provide、waterfall 语义均对齐它。
- **cordis**:npm `cordis`(koishi 生态)v4,前述内核的 JS 原版。
- **wasmtime 44**:运行时,提供 WASI p1、池化分配器、编译缓存。
- **WASI Preview 1**:插件与宿主的标准接口,也是"语言无关日志"的基础。
