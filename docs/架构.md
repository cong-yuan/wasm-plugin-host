> 面向**要改代码的人**。讲清分层、每个模块的职责、关键数据结构、以及最重要的几条数据流。

## 1. 分层

```
┌──────────────────────────────────────────────────────────────────┐
│  Supervisor (supervisor.rs)                                       │
│    读配置文件(desired state)· reconcile 收敛 · notify 监听变化     │
├──────────────────────────────────────────────────────────────────┤
│  Flow (flow.rs)                                                   │
│    run_turn:最小 agent 循环;每一步 dispatch 一个事件让插件介入      │
├──────────────────────────────────────────────────────────────────┤
│  Registry (registry.rs)        ← 管理面,外部主要接口              │
│    slot 元数据 · 工具表 · 钩子表 · 服务收敛 · 原子热更新            │
│  ┌────────────────┬─────────────────────┬─────────────────────┐   │
│  │ Hooks          │ Services            │ Tools               │   │
│  │ (hooks.rs)     │ (service.rs)        │ (in Registry)       │   │
│  │ 事件订阅+分发  │ 插件仓库+服务表+重入 │ name→handler 映射   │   │
│  └────────────────┴─────────────────────┴─────────────────────┘   │
├──────────────────────────────────────────────────────────────────┤
│  Plugin (plugin.rs)                                               │
│    一个 wasm 实例 · 生命周期状态机 · ABI 调用封装                  │
├──────────────────────────────────────────────────────────────────┤
│  Runtime (runtime.rs)                                             │
│    引擎 · 分配策略(按需/池化)· 编译缓存(mtime 键)· host.* 导入    │
│  State/Pipe (state.rs, pipe.rs)                                   │
│    HostState(每实例)· 有界日志 · WASI stdout/stderr 捕获           │
└───────────────────────────┬──────────────────────────────────────┘
                            │ wasmtime
                       插件实例(.wasm)
```

## 2. 关键数据结构

### 2.1 `Registry` —— 管理面

```rust
pub struct Registry {
    runtime: Runtime,
    shared: Arc<Shared>,                 // 插件实例仓库(guest 也能访问)
    meta: HashMap<String, SlotMeta>,     // slot → 元数据
    tools: HashMap<String, RegisteredTool>, // 工具名 → 绑定的 handler
    hooks: Hooks,                        // 事件订阅表
    log: Arc<LogSink>,                   // 共享有界日志
}
```

`SlotMeta` —— 每个 slot 的全部非实例状态:

```rust
struct SlotMeta {
    path: PathBuf,              // 当前 wasm 路径
    plugin_name: String,        // 插件自称的名字(可与 slot 不同)
    config: serde_json::Value,  // 当前生效配置(供 diff)
    injects: Vec<String>,       // 需要的服务
    provides: Vec<String>,      // 提供的服务
    active: bool,               // effects 是否已注册(inject 是否满足)
    owned_tools: Vec<String>,   // 激活时注册的工具(停用时精确回收)
}
```

### 2.2 `Shared` —— 插件实例仓库

**为什么单独存在**:一个正在运行的 guest 要能调另一个插件(`host.call_service`),
所以插件实例必须放在 `Arc` 后面,宿主和 guest 都能访问。

```rust
pub struct Shared {
    slots: Mutex<HashMap<String, Plugin>>,
    providers: Mutex<HashMap<String, String>>,  // 服务名 → 提供者 slot(仅 active)
}
```

### 2.3 `Plugin` —— 一个实例

```rust
pub struct Plugin {
    pub name, path, state, decl,       // 元信息
    store: Store<HostState>,           // 实例状态
    instance, memory,
    f_alloc, f_free, f_describe, f_invoke,     // 必需导出
    f_shutdown, f_configure, f_on_config,      // 可选导出
    config, config_version,            // 与 HostState 共享
}
```

### 2.4 `HostState` —— 每实例宿主状态(注入给 guest)

```rust
pub struct HostState {
    pub wasi: WasiP1Ctx,               // WASI 上下文(stdout/stderr 被我们接管)
    pub log: Arc<LogSink>,
    pub slot, plugin_name,
    pub config: Arc<Mutex<Value>>,     // 与 Plugin 共享,支持运行时改
    pub config_version: Arc<AtomicI64>,
    pub services: Option<Arc<Shared>>, // 跨插件调用用
}
```

## 3. 四条关键数据流

### 3.1 加载插件(含服务收敛)

```
Registry::load(slot, path, config)
  ├─ build_plugin() → Plugin::load()
  │     ├─ Runtime::compile(path)            # mtime 键控缓存
  │     ├─ 实例化 → 调 _initialize(Go reactor 需要)
  │     ├─ 校验 ABI 版本
  │     ├─ plugin_init
  │     ├─ plugin_configure(读 host.get_config)
  │     └─ plugin_describe → 解析 PluginDecl
  ├─ 校验:工具名冲突? 服务冲突? 事件名已知?
  ├─ shared.insert(slot, plugin)
  ├─ meta.insert(slot, SlotMeta{ active:false, ... })   # 先入待命
  └─ converge()                                # ★ 见 3.2
```

**关键**:插件先以 `active=false` 入库,再让 `converge` 决定是否激活。

### 3.2 服务收敛(converge)—— 系统的"灵魂"

```
loop {
  # 1. 停用:哪些 active 的插件 inject 已不满足?
  for slot where active && !all(injects satisfied) {
      deactivate(slot)      # 注销 tools/hooks/services
  }
  # 2. 激活:哪些待命插件的 inject 全满足了?
  for slot where !active && all(injects satisfied) {
      activate(slot)        # 注册 tools/hooks/services
  }
  if 无变化 { break }
}
```

`service_available(slot, svc)` 的判定:
- 该 slot 自己 provide 该服务 → 可用
- 否则:有 provider 且该 provider **处于 active** → 可用

**为什么会级联**:`activate(a)` 会注册 a 的 provides → 可能让 b 的 injects 满足 →
下一轮 `activate(b)` → 再点亮 c。实测三层链一趟点亮。

**注意**:`providers` 表里**只放 active 的插件**,所以收敛判定直接用 `shared.provider()`。

### 3.3 流程介入(dispatch)

```
Flow::run_turn
  dispatch(AgentPreStep, {input})
    ├─ hooks.has_subscribers? 否 → 直接返回,零开销
    ├─ 取订阅者列表(按 priority 排序)
    └─ 依次调用每个订阅者的 exec:
          payload = { event, value: 当前值 }
          reply = plugin.invoke_raw(exec, payload)   # 原始 JSON,不强校验形状
          if mode == waterfall:
              Decision::parse(reply)
                ├─ Continue → 不变
                ├─ Rewrite{value} → current = value   # 传给下一个订阅者的是改写后的值
                └─ Veto → 记 vetoed_by,break
          if mode == observe: 忽略 reply
          if 调用出错: 记入 errored,跳过(fail-open)
```

**两条不变式**:
1. **fail-open** —— 钩子报错或返回垃圾 → 当 `continue`,永不卡死流程
2. **链式可见** —— 每个订阅者看到的是"已被前面改写过"的值

### 3.4 跨插件服务调用(重入)

```
guest A 调 host.call_service("kv", "get", args)
  └─ host_call_service (runtime.rs)
       ├─ 从 caller 的线性内存读出 svc/op/args
       ├─ 克隆 Shared 句柄(不持有 store 借用!)
       ├─ shared.call_service("kv", "get", args)
       │    ├─ provider("kv") → slot
       │    └─ with_plugin(slot, ...):
       │         ├─ take(slot)              # ★ 把 callee 从仓库取出
       │         ├─ plugin.invoke_raw(...)
       │         └─ put(slot, plugin)       # 放回
       └─ 结果 JSON 写回 guest 的 out 缓冲
```

**重入为何安全**:
- callee 被**取出**后才能被调用 → store 锁**绝不跨 guest 调用持有** → 嵌套不死锁
- caller 在运行时**自己也不在仓库里** → A→B→A 时 A 已被取出 → 返回"busy"错误**而非死锁**

## 4. 模块职责速查

| 模块 | 职责 | 不负责 |
|---|---|---|
| `config.rs` | 配置 schema(desired state) | 收敛逻辑 |
| `state.rs` | `HostState`、`LogRecord`/`LogSink`(有界) | 日志从哪里来 |
| `pipe.rs` | WASI stdout/stderr → 日志行 | 日志存哪、怎么读 |
| `plugin.rs` | 一个实例的加载/调用/关闭/生命周期 | 插件间的协调 |
| `runtime.rs` | 引擎、分配策略、编译缓存、`host.*` 导入 | 插件语义 |
| `service.rs` | 插件仓库、服务表、重入保护 | 谁该 active(那是 converge) |
| `hooks.rs` | 事件词汇、`Decision`、订阅表、分发 | 事件何时触发(那是 flow) |
| `registry.rs` | slot 管理、工具表、收敛、原子热更新 | 流程本身 |
| `flow.rs` | 最小 agent 循环 + 事件派发点 | 真 LLM 调用(用 `Model` trait) |
| `supervisor.rs` | 配置文件收敛 + 文件监听 | 插件语义 |

**分层原则**:下层不知道上层。`plugin` 不知道 hooks;`hooks` 不知道 flow;
`flow` 不知道 supervisor。唯一的"上帝对象"是 `Registry`,它持有并协调一切。

## 5. 原子热更新的实现(stage-then-commit)

```
Registry::reload(slot, path, config)
  ── Stage 1:构建(不动任何 live 状态)──
     new_plugin = build_plugin()          # 完整加载+init+describe
     校验:工具名冲突? 服务冲突? 事件名?
     任何失败 → return Err,旧插件原封不动 ★

  ── Stage 2:提交(此后不再可能失败)──
     deactivate(slot)                     # 注销旧的 effects
     old = shared.take(slot); old.shutdown(); drop(old)   # 真释放
     shared.insert(slot, new_plugin)
     更新 meta
     converge()                            # 重新收敛,可能级联
```

这套结构保证了 R2(坏构建安全):**校验全在 Stage 1,提交在 Stage 2 且不可失败**。
测试 `reload_is_atomic_on_broken_build` 与 `demo/broken-build.sh` 验证。

## 6. WASI stdout/stderr 捕获(语言无关日志)

```
HostState::new()
  └─ pipe::log_pipes(log, slot, plugin) → (LogPipe, LogPipe)
       └─ WasiCtxBuilder::stdout(LogPipe).stderr(LogPipe)

guest println! / fmt.Println / console.log
  └─ WASI fd_write(1 或 2)
       └─ LogPipe::async_stream() 返回的 AsyncWrite
            └─ PipeState::feed(bytes)   # 按 '\n' 切行,处理 CRLF 与跨 write 部分行
                 └─ LogSink::push(LogRecord{seq, slot, plugin, level, message})
```

`stdout → Info`,`stderr → Error`;`drop` 时 flush 无换行的尾行。
**这就是"任何语言零胶水"的原理** —— 因为所有语言的 print 都走 WASI fd_write。

## 7. 为什么没有全局锁

系统里只有两把锁,且都**极短暂**:
- `Shared.slots` / `Shared.providers` 的 `Mutex` —— 只在 insert/take/put/查询时持有
- `LogSink` 内部的 `Mutex` —— 只在 push/snapshot 时持有

**关键纪律**:任何**跨 guest 调用**(`invoke`/`invoke_raw`/`dispatch`/`call_service`)
**都不在持锁状态**。做法是先把需要的句柄/插件**取出**,释放锁,再调用。
这是重入安全的根本。

## 8. 扩展点(给将来)

| 要加的东西 | 改哪里 | 是否影响接口 |
|---|---|---|
| 新事件 | `hooks.rs::Event` 枚举 + `flow.rs` 的派发点 | ABI 的 `on` 字符串 |
| 新 host 导入 | `runtime.rs` 的 linker + 文档 | ABI 文档 |
| 新分配策略 | `runtime.rs::AllocationStrategy` | 无 |
| **JS/Python 支持** | `runtime.rs::Runtime`(core module → component backend) | ABI 语义不变,底层换 |
| 权限模型 | `state.rs::HostState`(收窄 WASI ctx)+ `runtime.rs` | 无(对插件透明) |

**`Runtime` 被刻意设计成唯一知道"core module"的地方** —— 将来接 Component Model 只需换后端。
