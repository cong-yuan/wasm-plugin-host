# 使用指南

> 面向**上手的人**:从零构建、跑起来、写第一个插件、嵌入到自己的 App。
> 契约细节看 [ABI.md](ABI.md)。

---

## 1. 环境要求

| 工具 | 版本 | 用途 |
|---|---|---|
| Rust | 1.92+ | 构建宿主 |
| `wasm32-wasip1` target | — | 构建 Rust 插件 |
| Go | 1.26+ | (可选)构建 Go 插件 |
| Node.js | 22+ | (可选)只用于检查 wasm 的 import/export |

```sh
rustup target add wasm32-wasip1
```

---

## 2. 构建与运行

```sh
cd ~/wasm-plugin-host

# 1. 构建宿主(原生)
cargo build --release

# 2. 构建示例插件(注意目标是 wasm32-wasip1,不是原生)
cargo build --release -p hello-rust --target wasm32-wasip1
# 产物: target/wasm32-wasip1/release/hello_rust.wasm

# 3. 交互式宿主
./target/release/plugin-host
```

### 交互式命令

```
load <slot> <wasm>          把 wasm 加载进 slot
unload <slot>               关闭并释放
reload <slot>               从 wasm 热更新(原子)
enable / disable <slot>     调整期望状态并写回配置
reconcile                   立即按配置收敛
reconfig                    重新读配置文件
refresh                     清空编译缓存
watch [on|off]              开关文件监听
plugins                     列出插件(含 active/quiescent)
tools                       列出工具
call <tool> '<json>'        调用工具
logs [slot] [n]             查看日志
clear-logs | status | config | quit
```

### 一次性执行 / 守护模式

```sh
# 执行单条命令后退出
./target/release/plugin-host load greet target/wasm32-wasip1/release/hello_rust.wasm

# 绑定配置 + 监听文件,自动热更新(守护)
./target/release/plugin-host --config demo/live.json --supervise
```

### 跑示例

```sh
cargo run --release --example intervene   # 插件 veto 流程 → 卸载 → 流程恢复
cargo run --release --example services    # 服务收敛 + 跨插件调用
cargo run --release --example parallel    # 池化分配 + 并行调用
```

### 跑 demo 脚本

```sh
./demo/hotreload.sh        # 换 wasm → 热更新
./demo/broken-build.sh     # 坏 wasm → 拒绝,旧插件继续跑
./demo/config-live.sh      # 改一个插件配置 → 只更新它
./demo/config-restart.sh   # restart_on_config → 只重启该插件
```

### 跑测试

```sh
cargo test --release       # 35 个(32 集成 + 3 单元)
```

## 3. 配置文件

配置描述**期望状态**,`reconcile` 让运行中的宿主对齐它。

```json
{
  "watch": { "enabled": true, "interval_ms": 400 },
  "cache": { "dir": ".cwasm-cache", "enabled": true },
  "plugins": {
    "greet": {
      "path": "../target/wasm32-wasip1/release/hello_rust.wasm",
      "enabled": true,
      "config": { "greeting": "Hello" },
      "restart_on_config": false,
      "watch": true
    },
    "extra": { "path": "extra.wasm", "enabled": false }
  }
}
```

| 字段 | 说明 |
|---|---|
| `plugins.<slot>.path` | wasm 路径,**相对配置文件所在目录** |
| `enabled` | 是否应加载;`disable` 会写回此字段 |
| `config` | 任意 JSON,**注入**插件(见下) |
| `restart_on_config` | `false`(默认)实时推送配置;`true` 则**重启该插件**以重新读取 |
| `watch` | 该插件是否参与自动热更新,覆盖全局 |
| `watch.enabled` / `interval_ms` | 全局监听开关 / notify 的兜底轮询间隔 |
| `cache.dir` / `cache.enabled` | 磁盘预编译缓存目录(相对配置文件目录)/ 开关 |

**配置只影响变了的插件**:改一个 slot 的 `config`,只有它会更新,其他原封不动。

### 磁盘编译缓存(P2)

开启 `cache` 后,首次加载会把预编译产物写成 `.cwasm`;之后**每次进程重启**
直接反序列化,不再编译。实测(Go 插件,10.6 MB)冷启动 **~258 ms → ~7 ms(~36x)**。

```sh
cargo run --release -p wasm-plugin-host --example bench_cache   # 看加速
./demo/cache.sh                                                 # 两次跑对比计数
```

REPL 里:`cache` 看 `hits/misses/writes/errors`;`refresh` 同时清内存 + 磁盘缓存。

> **信任边界**:反序列化 `.cwasm` 在 wasmtime 里是 `unsafe` —— 产物被假定来自兼容引擎。
> 所以**缓存目录必须只有宿主可写**(和任何构建缓存一样)。产物是**原子写入**的
> (temp + rename),崩溃不会留下半截文件;坏产物会被删掉并自动重编译。

## 4. 写第一个插件(Rust)

### 4.1 最小骨架

必须导出(见 [ABI.md](ABI.md)):

```rust
//! 最小插件:一个工具 + 一条日志。

// 宿主提供的导入
#[link(wasm_import_module = "host")]
extern "C" {
    fn log(level: i32, ptr: *const u8, len: usize);
}

fn host_log(level: i32, msg: &str) {
    unsafe { log(level, msg.as_ptr(), msg.len()) }
}

#[no_mangle] pub extern "C" fn plugin_abi_version() -> i32 { 1 }

#[no_mangle]
pub extern "C" fn plugin_init() -> i32 {
    println!("demo: init");   // 或 host_log;println 会被自动捕获
    0
}

#[no_mangle] pub extern "C" fn plugin_shutdown() {}

#[no_mangle]
pub extern "C" fn plugin_alloc(n: i32) -> i32 {
    let mut v = Vec::<u8>::with_capacity(n.max(0) as usize);
    let p = v.as_mut_ptr() as i32;
    std::mem::forget(v);          // 宿主负责 free
    p
}
#[no_mangle] pub extern "C" fn plugin_free(p: i32, n: i32) {
    unsafe { let _ = Vec::from_raw_parts(p as *mut u8, 0, n.max(0) as usize); }
}

#[no_mangle]
pub extern "C" fn plugin_describe(out: i32, cap: i32) -> i64 {
    let decl = r#"{"name":"demo","abi":1,"tools":[
        {"name":"hello","description":"say hi","exec":"hello"}]}"#;
    write_out(out, cap, decl.as_bytes())
}

#[no_mangle]
pub extern "C" fn plugin_invoke(
    op_ptr: i32, op_len: i32, args_ptr: i32, args_len: i32, out: i32, cap: i32,
) -> i64 {
    let op = unsafe { read_str(op_ptr, op_len) };
    let result = match op.as_str() {
        "hello" => r#"{"kind":"success","content":"hi!","value":{}}"#.to_string(),
        other   => format!(r#"{{"kind":"error","message":"unknown op {other}"}}"#),
    };
    write_out(out, cap, result.as_bytes())
}

// ---- 帮助函数 ----
unsafe fn read_str(ptr: i32, len: i32) -> String {
    if ptr == 0 || len <= 0 { return String::new(); }
    String::from_utf8_lossy(std::slice::from_raw_parts(ptr as *const u8, len as usize)).into_owned()
}
fn write_out(out: i32, cap: i32, src: &[u8]) -> i64 {
    if out == 0 || src.len() > cap.max(0) as usize { return -(src.len() as i64); }
    unsafe { std::ptr::copy_nonoverlapping(src.as_ptr(), out as *mut u8, src.len()); }
    src.len() as i64
}
```

`Cargo.toml`:
```toml
[package]
name = "demo"
version = "0.1.0"
edition = "2021"
[lib]
crate-type = ["cdylib"]
```

构建:
```sh
cargo build --release --target wasm32-wasip1
```

> **注意**:插件 crate 必须**从工作区的默认构建中排除**(它的 `host.*` 导入无法原生链接)。
> 本项目在根 `Cargo.toml` 用 `default-members = ["host"]` 实现这一点。

### 4.2 加一个钩子(介入流程)

在 `plugin_describe` 的 JSON 里加 `hooks`:

```json
{
  "name": "guard",
  "abi": 1,
  "tools": [],
  "hooks": [ { "on": "tools/pre-execute", "exec": "check", "mode": "waterfall" } ]
}
```

`plugin_invoke` 里处理 `exec == "check"`,返回一个**决策**:

```rust
"check" => {
    // 想否决就返回:
    r#"{"kind":"veto","reason":"blocked by policy"}"#.to_string()
    // 想放行:  r#"{"kind":"continue"}"#
    // 想改写:  r#"{"kind":"rewrite","value":{"turn":1,"name":"x","args":{...}}}"#
}
```

### 4.3 声明服务(inject / provide)

```json
{
  "injects": ["kv"],
  "provides": ["report"]
}
```

- `injects` 未满足 → 插件**静默待命**(工具不注册)
- 所有 `injects` 满足 → **自动激活**
- 调用别的服务:用 `host.call_service`

## 5. 写一个 Go 插件

Go 也能编译到 WASI,且**用惯用打印就自动出日志**:

```go
package main

import (
    "encoding/json"
    "fmt"
    "unsafe"
)

var live = map[uint32][]byte{}  // 防止 GC 回收宿主持有的指针

//go:wasmexport plugin_abi_version
func abi() int32 { return 1 }

//go:wasmexport plugin_alloc
func alloc(n int32) int32 {
    if n <= 0 { n = 1 }
    b := make([]byte, n)
    p := uint32(uintptr(unsafe.Pointer(unsafe.SliceData(b))))
    live[p] = b
    return int32(p)
}
//go:wasmexport plugin_free
func free(p, n int32) { delete(live, uint32(p)) }

//go:wasmexport plugin_init
func init_() int32 {
    fmt.Println("hello from Go")          // ← 自动变成日志
    fmt.Fprintln(os.Stderr, "diagnostic") // ← stderr → error 级
    return 0
}
//go:wasmexport plugin_shutdown
func shutdown() {}

//go:wasmexport plugin_describe
func describe(out, cap int32) int64 {
    d := `{"name":"goplug","abi":1,"tools":[{"name":"go_tool","description":"d","exec":"go"}]}`
    if int32(len(d)) > cap { return -int64(len(d)) }
    copy(unsafe.Slice((*byte)(unsafe.Pointer(uintptr(out))), len(d)), d)
    return int64(len(d))
}
//go:wasmexport plugin_invoke
func invoke(a, b, c, d, out, cap int32) int64 {
    r := `{"kind":"success","content":"ok","value":{}}`
    copy(unsafe.Slice((*byte)(unsafe.Pointer(uintptr(out))), len(r)), r)
    return int64(len(r))
}

func main() {}
```

构建:
```sh
GOOS=wasip1 GOARCH=wasm go build -buildmode=c-shared -o hello_go.wasm .
```

**要点**:
- Go 是 **reactor** 模块,导出 `_initialize`,宿主会自动调用(已处理)
- Go 每实例约 **2.6 MB**(内置 runtime);Rust 约 **119 KB** → 插件量大时优先 Rust
- 用 `//go:wasmexport` 导出、`//go:wasmimport host <name>` 导入

## 6. 嵌入到自己的 App(Tauri 等)

宿主是**库**,CLI 只是薄壳。

```rust
use wasm_plugin_host::{Registry, Runtime, LogHook, LogRecord};
use std::sync::Arc;

// 可选:把插件日志转发到你的 UI / Tauri 事件
let hook: LogHook = Arc::new(|rec: &LogRecord| {
    // app.emit("plugin-log", rec)?;
    println!("{}", rec.render());
});

let mut reg = Registry::with_logging(Runtime::new()?, 1000, /*echo*/ false, Some(hook));

// 加载
reg.load("greet", "greet.wasm".as_ref(), serde_json::json!({}))?;

// 调用工具
let out = reg.call_tool("greet", &serde_json::json!({ "who": "world" }))?;

// 派发流程事件(让插件介入)
let d = reg.dispatch(wasm_plugin_host::FlowEvent::AgentPreStep,
                     serde_json::json!({ "turn": 1, "input": "hi" }));
if let Some(by) = d.vetoed_by { /* 被某个插件否决了 */ }

// 原子热更新
reg.reload("greet", "greet-v2.wasm".as_ref(), None)?;
```

### 与配置文件/监听一起用

```rust
use wasm_plugin_host::Supervisor;

let mut sup = Supervisor::new("plugins.json".as_ref())?;
for ev in sup.reconcile(&mut reg) { println!("{}", wasm_plugin_host::render(&ev)); }

// 事件驱动监听(自动热更新)
let watcher = sup.watcher()?;
loop {
    if let Some(w) = &watcher { w.wait(sup.interval()); }
    for ev in sup.poll_changes(&mut reg) { println!("{}", wasm_plugin_host::render(&ev)); }
}
```

> **提醒**:`Registry` 是 `Send` 但不是 `Sync`(实例单线程)。要跨线程共享,
> 用 `Arc<Mutex<Registry>>`。**不要跑不可信插件**——还没权限模型(P0)。

## 6b. 把插件接进 dsh agent harness(`dsh-wasm-host`)

如果你的上层是一个 **dsh-rs**(cordis)agent harness,不要自己写编排:
用 `dsh-wasm-host` crate,一行装载,插件工具就出现在 dsh 的 `ctx.tools` 上,
并由 dsh **真实 agent loop** 驱动。

```rust
use dsh_wasm_host::{install, LoadSpec, WasmHost};

let ctx = cordis::Context::new();
dsh_rs::bundle::install_base_default(&ctx).await?;   // 启动 dsh 基座

let host = WasmHost::new()?;
install(&ctx, host.clone(), vec![
    LoadSpec::new("greet", "target/wasm32-wasip1/release/hello_rust.wasm")
]).await?;

// 现在 agent loop 里模型可以直接调用 guest 的 `greet` 工具
```

端到端可跑示例:

```sh
cargo build --release -p hello-rust --target wasm32-wasip1
cargo run -p dsh-wasm-host --example compose
```

**热更新后同步工具面**:

```rust
let mut tracked = vec!["greet".to_string()];
host.reload("greet", "greet-v2.wasm", None)?;
let (added, removed) = dsh_wasm_host::plugin::resync_tools(&tools, &host, &mut tracked);
```

**决策翻译对照表**(guest 说什么 → dsh 哪个点):

| dsh 点 | guest `veto` | guest `rewrite` |
|---|---|---|
| `tools/pre-execute` | → `{kind:"deny"}` | 忽略(dsh 此点不收参数重写)|
| `agent/pre-step` | → `{kind:"reject"}` | → `{kind:"enter", messages}` |
| `agent/request` | 忽略(无拒绝词汇) | → 替换 `LlmCallConfig` |
| `session/event` | — | —(只观察)|

详见 [`dsh-wasm-host/README.md`](../dsh-wasm-host/README.md)。

> **为什么不在 `host/` 里做?** dsh 本身已是完整 cordis 内核 + agent harness;
> 把 WASM 运行时作为**插件插进去**比在 Tauri 层重写编排更符合 dsh 的模型。
> 而且 dsh 已有的插件宿主是 `dlopen`/cdylib(永不卸载),本 crate 补的是**它的 WASM 版**。

## 7. 常见问题

**Q: 插件加载报 "missing export plugin_alloc"**
→ 插件必须导出 ABI 的全部必需符号,见 [ABI.md](ABI.md)。

**Q: Go 插件报 "wasmexport function called before runtime initialization"**
→ 老版本宿主的问题;当前宿主会自动调用 `_initialize`。确认你用的是最新代码。

**Q: 插件日志没出来**
→ 插件用 `println!`/`fmt.Println` 即可(走 WASI stdout,自动捕获)。
若宿主 `echo_stderr=false`,用 `logs` 命令或 `LogHook` 读取。

**Q: 插件加载了但 `tools` 里没有它**
→ 它可能是 **quiescent**(`injects` 未满足)。看 `plugins` 命令的输出或
`LoadedReport.missing_services`。

**Q: 想在自己的 crate 里用插件的 wasm**
→ `cargo build -p <plugin> --target wasm32-wasip1`,产物在 `target/wasm32-wasip1/release/`。

**Q: 编译缓存何时失效?**
→ 按**文件 mtime**。重编译覆盖同一路径的 `.wasm` 会自动触发重编译。
手动清:`Registry::runtime().clear_cache()` 或 `refresh` 命令。
