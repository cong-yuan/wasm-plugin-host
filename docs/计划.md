## P0 —— 权限 / 能力模型 🔴

**为什么最重要**:当前插件拿到**完整 WASI**(能读写任意文件、访问网络)。
这意味着现在**不适合跑第三方不可信插件**。不解决这个,这个宿主只能用于"自己写的、可信的"插件。

### 要做的事

1. **收窄 WASI 上下文**
   - 默认**不给**任何文件系统/网络能力
   - 用 `WasiCtxBuilder` 的 preopen 白名单:`--allow-dir <path>` 才暴露目录
   - 网络:默认关闭(需要则显式开启并限目标)

2. **资源上限**
   - **fuel**:限制指令数(防死循环);`Config::consume_fuel(true)` + `Store::set_fuel`
   - **内存上限**:限制线性内存增长(`StoreLimits` / 池化的 `max_memory_size`)
   - **时间上限**:调用级超时

3. **配置化的能力声明**
   - 配置文件每个插件单元增加 `permissions` 字段:
     ```json
     "greet": {
       "path": "...",
       "permissions": {
         "read_dirs":  ["/tmp/sandbox"],
         "write_dirs": ["/tmp/sandbox"],
         "network":    false,
         "max_memory_mb": 64,
         "max_fuel": 100000000,
         "timeout_ms": 5000
       }
     }
     ```
   - 无 `permissions` → 默认**最小权限**(什么都不给)

4. **能力 API**(可选,更细粒度)
   - 用 `host.fs_read` / `host.net_fetch` 这类显式导入替代裸 WASI
   - 宿主在这些导入里做路径校验与限流

### 验收标准

- [ ] 一个"恶意"插件尝试 `open("/etc/passwd")` → 返回权限错误,**不是**成功
- [ ] 一个死循环插件 → 在 fuel 耗尽后**被终止**,宿主不受影响
- [ ] 一个疯狂分配内存的插件 → 在内存上限处失败,宿主 RSS 不飙升
- [ ] 配置 `permissions.read_dirs: ["/tmp/x"]` 后,插件**只能**读 `/tmp/x`
- [ ] 新增测试:`permission_denied_without_grant`、`fuel_exhaustion_terminates_plugin`、
      `memory_limit_enforced`、`preopen_whitelist`
- [ ] 文档:在 [ABI.md](ABI.md) 与 [使用指南.md](使用指南.md) 增加"权限"章节

### 风险 / 注意
- WASI p1 的能力模型本身较粗(基于 preopen fd);细粒度需要自定义导入
- fuel 会带来性能开销,默认应关闭、按插件开启

## P1 —— dsh 集成:`dsh-wasm-host` crate ✅ 已完成

**方向变更**:原计划是“把 Registry 接进 Tauri”。现已改为**新建一个 crate**,
**组合 dsh 与插件系统**,而**不在 `host/` 上改动**。理由:

- dsh 本身就是一个完整的 cordis 内核 + agent harness;把 WASM 运行时**插进去**
  比在 Tauri 层重写一遍编排更符合 dsh 的“一切皆插件”模型。
- dsh **已有**动态插件宿主,但是 `dlopen`/cdylib(`bundle::dynamic`):
  代码映射进来就**永不卸载**,插件崩溃能带崩宿主。
- `dsh-wasm-host` 就是它的 **WASM 版**:真释放 + 坏构建拒换。这是 dsh 缺的那一环。

### 已完成

- 新 crate `dsh-wasm-host`(依赖 `wasm-plugin-host` + `dsh-rs 0.2.0` + `cordis-rust 0.2.1`)
- **工具桥**:guest 工具 → dsh `ctx.tools` 的 dynamic tool;exec 回落到 `Registry::call_tool`
- **流程桥**:`agent/pre-step`、`agent/request`、`tools/pre-execute` ↔ WASM hook 总线,
  含决策翻译;`session/event` → observe 钩子扇出
- **生命周期**:cordis plugin + fiber effect,卸载自动反注册;`resync_tools` 处理热更新后的工具面
- 11 个集成 + 12 个单元 + 1 doctest;`examples/compose.rs` 端到端可跑

**验收**:
- [x] WASM 插件的工具注册到 `ctx.tools`
- [x] dsh **真实 agent loop** 驱动 guest 工具,结果进 session
- [x] guest `veto` 在 `tools/pre-execute` 拦截工具调用(经真实 agent loop)
- [x] guest `veto` 在 `agent/pre-step` 拒绝整个 turn
- [x] fiber 卸载后工具从 `ctx.tools` 消失

### 遗留(可后续做)

- [ ] 桥接 `tools/execute` / `tools/post-execute`(需引入参数重写)
- [ ] 把 guest veto 的 reason 传到 dsh(需 host `Dispatch` 加字段)
- [ ] 磁盘编译缓存(见 P2)

## P2 —— 磁盘编译缓存 ✅ 已完成

**为什么**:只在**进程内**缓存时,每次重启都要重编译(Go 插件实测 ~260 ms)。

### 已实现
- `Runtime::new_cached(dir)` / `with_disk_cache(strategy, dir)`
- 缓存键:**wasm 内容 hash**(FNV-1a)+ **引擎指纹**(wasmtime 兼容 hash + 分配策略)
- **原子写入**(temp + rename)、**坏产物自愈**、**引擎变化自动失效**
- 配置:`{ "cache": { "dir": "...", "enabled": true } }`;CLI `cache` / `refresh`
- 信任边界已在代码里标注(反序列化 `.cwasm` 是 unsafe,缓存目录必须只有宿主可写)

### 验收标准

- [x] 首次启动编译并写 `.cwasm`;二次启动直接反序列化(`hits 1 / misses 0`)
- [x] 实测加速:**258 ms → 7.3 ms(~36x)**(Go 插件,10.6 MB,release)
- [x] 引擎配置变化(分配策略不同)→ 指纹不同 → 自动失效重编译
- [x] 新增测试:`cold_compile_writes_a_cwasm_and_warms_on_second_load`、
  `engine_change_invalidates_the_disk_cache`、`corrupted_artifact_is_dropped_and_recompiled` 等 8 个

## P3 —— 增强项 🟢

### P3.1 工具级依赖编排
- 现在已有 tool/hook/service。可加"工具依赖工具"(A 的工具需要 B 的工具先可用)
- 或"工具提供/消费"更细的图
- **验收**:一个带依赖的工具链能自动排序/激活

### P3.2 JS / Python(Component Model)
- `Runtime` 是唯一知道"core module"的地方 —— 加 `ComponentBackend` 即可
- JS 用 `jco`、Python 用 `componentize-py`,产出 **Component** 而非 core module
- ABI 从"JSON over linear memory"换成 **WIT 类型化接口**
- **Registry / Plugin 生命周期层完全不变**
- **验收**:一个 JS 写的插件能加载、能出日志、能被调用

### P3.3 日志级别过滤
- 配置文件加 `log_level`;低于阈值的记录丢弃
- CLI `logs --level warn`
- **验收**:`log_level: "warn"` 时 debug/info 不出现

### P3.4 配置 schema 校验
- 配置加载时校验字段(路径存在性、枚举值)
- 错误信息精确到字段
- **验收**:坏配置给出明确错误而非静默忽略

### P3.5 `notify` 之外的 .watcher 优化
- 目前 notify + 80ms 去抖已够用
- 可选:批量事件合并、inotify 溢出处理

```
P0 权限模型 ────────────┐
                        ├─→ (产品可用)
```

- P2 独立,可与 P0 并行,收益是启动速度
- P3 都是锦上添花
