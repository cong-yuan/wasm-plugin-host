### 1.10 磁盘编译缓存(P2)✅
- `Runtime::new_cached(dir)` / `with_disk_cache(strategy, dir)` 开启 `.cwasm` 缓存
- 缓存键:**wasm 内容 hash** (FNV-1a) + **引擎指纹**(wasmtime 兼容 hash + 分配策略)
- **原子写入**:先写临时文件再 rename,崩溃不会留下半截 `.cwasm`
- **引擎配置变化自动失效**:不同策略 → 不同指纹 → 不复用旧产物
- **坏产物自愈**:反序列化失败 → 删掉并重编译,不让加载失败
- 配置项:`{ "cache": { "dir": "...", "enabled": true } }`(相对路径按配置文件目录解析)
- CLI:`cache` 看计数(hits/misses/writes/errors);`refresh` 同时清内存 + 磁盘
- **信任边界**:反序列化 `.cwasm` 是 `unsafe`(wasmtime 语义);缓存目录必须只有宿主可写。
  代码里已明确标注这一点。

**实测**(Go 插件,10.6 MB 模块,Apple M2 Pro,release,`examples/bench_cache.rs`):
| | load() 墙钟 |
|---|---|
| 无缓存 | 279 ms |
| 冷(编译 + 写 `.cwasm`)| 258 ms |
| **热(反序列化)** | **7.3 ms** |
| **加速** | **~36x** |

### 1.14 每个 WASM slot = 一个 cordis 插件(dsh-wasm-host,B)✅
**之前**:不管几个 wasm,只挂**一个** cordis plugin / 一个 fiber —— wasm 的
`injects`/`provides` 是**孤儿**,dsh 完全看不见。

**现在**:每个 slot 挂**自己的** cordis plugin:
- **独立 fiber**:独立生命周期与收敛状态;`mounted.slot_fiber(slot)` 单独 dispose
- **`injects` → cordis `Injection`**:依赖未满足时 fiber 停在 **PENDING**
  (cordis 自己把门),满足才激活;依赖可由**另一个 wasm slot** 的 `provides`
  或**dsh 服务**满足(`WasmHost::declare_dsh_service` 把 dsh 服务声明给 wasm registry)
- **`provides` → `ctx.provide`**:slot 声明的服务以 [`WasmService`] 发布到 context,
  **任何** dsh 插件(原生或 wasm)都能 `ctx.require::<WasmService>("memory")` 并 `.call(op, json)`;
  slot 卸载时服务自动撤回
- **真卸载**:dispose slot fiber 会 drop wasmtime 实例(代码 + 线性内存真释放)
- **两个收敛循环保持一致**:cordis 是权威门;wasm registry 的 `force_activate`/`force_deactivate`
  镜像 cordis 的决定,dsh 服务经 `Shared::add_external_provider` 声明为 external

**验证**(9 个,均已确认"破坏该功能则测试失败",非空洞):
`each_slot_gets_its_own_fiber`、`a_slot_stays_pending_until_its_inject_is_provided`、
