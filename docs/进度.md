## 1. 已完成(带验证)

### 1.1 插件生命周期 ✅
- 运行时 `load` / `unload` / `reload`
- 卸载**真释放**代码 + 线性内存(WASM `drop`)
- slot 作为**稳定身份**,插件内部改名不影响热更新
- ABI 版本门禁(v1)

**验证**:`load_then_unload_releases_slot`、`reload_swaps_code_and_keeps_slot_identity`、`validate_compiles_without_swapping`

### 1.2 原子热更新 + 坏构建安全 ✅
- stage-then-commit:先完整校验新构建,全部通过才拆旧的
- 失败(坏 wasm / ABI 不符 / 缺导出 / 工具名冲突 / 服务冲突 / 未知事件)→ 旧插件原样运行

**验证**:`reload_is_atomic_on_broken_build`、`reload_rejected_when_new_tool_collides_with_other_slot`、`demo/broken-build.sh`

### 1.3 流程介入(hooks) ✅
- 9 个事件:`turn/start`、`agent/pre-step`、`agent/request`、`llm/chunk`、`assistant/message`、`tool/call`、`tools/pre-execute`、`tool/result`、`turn/end`
- 两种模式:`observe`(只读)/ `waterfall`(可 `continue`/`rewrite`/`veto`)
- **fail-open**:钩子报错或返回垃圾 → 当 continue,永不卡死
- **链式可见**:每个 waterfall 订阅者看到的是"已被前面改写"的值
- `priority` 支持排序

**验证**:`plugin_can_veto_the_flow`、`observe_hook_cannot_change_flow`、`unknown_event_is_rejected_at_load`、`examples/intervene.rs`

### 1.4 服务图 + 响应式收敛 ✅
- `injects` / `provides`,服务名冲突拒绝
- **quiescent**:inject 未满足 → 加载但不注册 effects
- **响应式收敛**:provider 出现 → consumer 自动激活;**级联**(三层链一趟点亮)
- provider 消失 → 级联停用
- **跨插件调用** `host.call_service`(按服务名)+ `host.has_service`
- **重入安全**:嵌套可调;直接递归报 "busy" 而非死锁
- 无 provider 时返回 JSON error,**不 trap**

**验证**:`consumer_stays_quiescent_until_provider_appears_then_converges`、
`deeper_chain_converges_in_one_pass`、`self_provided_service_activates_immediately`、
`two_plugins_cannot_provide_the_same_service`、`plugin_can_call_another_plugin_by_service_name`、
`service_call_without_provider_returns_error_not_trap`、`recursive_service_call_is_refused_not_deadlocked`、
`reload_respects_service_graph`、`unload_removes_hooks_and_services`、`examples/services.rs`

### 1.5 配置驱动 + 逐插件实时更新 ✅
- 配置文件(desired state)+ `reconcile`
- 配置**注入**插件(`plugin_configure` + `host.get_config`)
- **只更新配置变了的插件**(逐 slot diff)
- 两种策略:`restart_on_config` false=实时推送 / true=重启该插件
- 配置文件本身被监听(外部编辑自动生效);坏配置保留上一份好配置
- `enable`/`disable` 写回文件

**验证**:`load_injects_config`、`apply_config_reports_consumed_and_is_idempotent`、
`config_change_to_one_slot_leaves_the_other_untouched`、`reload_can_carry_a_new_config_atomically`、
`supervisor_updates_only_changed_slot_via_reconcile`、`demo/config-live.sh`、`demo/config-restart.sh`

### 1.6 语言无关日志 ✅
- **捕获 WASI stdout/stderr**:任何语言的 print 零胶水
  (Rust `println!` / Go `fmt.Println` / C `printf` / JS `console.log` / Python `print`)
- stdout→Info,stderr→Error;按行切分,跨 write 部分行、CRLF、drop flush 都处理
- **有界环缓冲**(默认 1000,不泄漏)
- 读取 API:`logs()` / `logs_for(slot)` / `logs_since(seq)`
- **LogHook 回调**(转发到 UI / Tauri)
- 可选 `host.log` 做结构化级别升级

**验证**:`guest_stdout_and_stderr_are_captured_as_logs`、`plugin_logs_are_captured_with_slot_prefix`、
`log_buffer_is_bounded`、`log_hook_receives_every_record`、`standalone_sink_bounds_and_tails`、
3 个 pipe 单元测试

### 1.7 并发 ✅
- **池化分配器**(`AllocationStrategy::Pooled`):预保留实例槽,实例化可预测
- **并行调用** `call_many_parallel`:不同 slot 并行,同 slot 串行,结果保持输入顺序
- `Store<T>` **是 `Send`**(已实测),可跨线程移动;非 `Sync`(单线程使用)

**验证**:`pooled_allocator_loads_and_calls`、`parallel_calls_across_slots_run_and_preserve_order`、
`parallel_calls_with_unknown_tool_return_errors_in_place`、`examples/parallel.rs`

### 1.8 文件监听(notify)✅
- `notify` crate,监听插件文件**父目录**(抗原子替换)+ 配置文件
- 80ms 去抖;`wait(fallback)` 事件驱动,带兜底超时
- 平台不支持时回退轮询并**明确提示**

**验证**:`notify_watcher_fires_on_file_change`;实测 30s fallback 下延迟 **~136ms**

## 2. 实测数据(Apple M2 Pro, wasmtime 44, release)

### 单次启停
| | Rust 插件 | Go 插件 |
|---|---|---|
| load(init+describe) | 54 µs | 358 µs |
| 调用工具 | 6.9 µs | 29.8 µs |
| drop(真卸载) | 7.8 µs | 18 µs |
| 完整周期 | ~135 µs | ~530 µs |

### 100 实例常驻
| | Rust | Go |
|---|---|---|
| RSS | ~12 MB(119 KB/个)| ~261 MB(2.6 MB/个)|
| 加载/卸载 100 个 | 5.2 / 0.87 ms | 37.7 / 4.9 ms |

### 基础开销
- 实例化:~5 µs/个(编译只做一次)
- 空闲实例内存:~6 KB/个(线性内存懒提交)
- 计算 ≈ 原生 0.95x;跨边界调用 +16 ns
- 3000 次循环 RSS 稳定 → 无泄漏
